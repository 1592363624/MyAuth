## 重启方式变更（2026-08-01 晚）

- **决策：弃用宝塔面板 API 重启，改用 SSH 脚本「杀进程 + 启动 jar」的进程模式。**
- 原因：用户认为调宝塔 API 需配 IP 白名单/API Key 太麻烦，且希望脚本直接可控。
- 健壮性设计（核心诉求：更新成功或失败都要保证后端能起来，不能雪崩）：
  1. 启动前备份旧 jar 为 `myauth.jar.bak`；
  2. 用 WMI（`Win32_Process` 按 CommandLine 匹配）精准停止旧 java 进程；
  3. 启动后用 TCP 轮询 6401 端口（最多 90s）确认存活；
  4. 新 jar 起不来 → 自动回滚 `myauth.jar.bak` 并重启旧版本；
  5. 兜底：新旧都失败才抛错让 Actions 标红。
- 启动命令与宝塔一致：`C:\BtSoft\jdk\jdk17\bin\java.exe -jar -Xmx1024M -Xms256M myauth.jar --server.port=6401`

## 架构与部署复杂度分析（后续对话）

- 用户反馈「打包和前后端分离导致部署麻烦」。结论：架构选型（Spring Boot + Vue 分离）本身没问题，痛点是缺少部署工程化收口（双独立构建 + Nginx 拼装）。

- 给出四方案：A 后端托管静态（零 Nginx）、B Maven frontend-maven-plugin 一体化（推荐，改动小）、C Docker+compose、D Nginx 模板化。
